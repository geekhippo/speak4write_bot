## AI News Fixes (после фидбэка)

- **Проблема:** Каждый вызов `/ainews` показывал одни и те же новости (всегда первая статья из RSS)
- **Решение:** Добавлен `_seen_urls` (модульный `set[str]`) — при каждом вызове `get_next()` возвращается первая НЕПОКАЗАННАЯ новость из ленты каждого источника
- **Циклический сброс:** Когда все источники исчерпали непоказанные новости — `_seen_urls.clear()`, цикл начинается заново
- **Кэш ленты:** RSS-ленты кэшируются на 30 минут (`_FEED_CACHE_TTL = 1800`), чтобы не ддосить источники
- **Отключён web preview:** `disable_web_page_preview=True` в `/ainews`
- **Дедикация:** Перед сборкой дайджеста применяется `_dedup_by_title()` (из основного кода) — если два источника пишут об одном, остаётся только первый

## Bug Fix: Repeated Old News in Main Digest (2026-06-26 06:09-11:00 UTC)

### Bug #1 — Midnight cleanup runs at any restart time
- `_news_loop` in `bot.py`: `last_cleanup_date = None`, so `last_cleanup_date != today` was **always True on first run** regardless of time of day.
- At 06:15 restart, it set ALL 1404 old news → `is_sent=0`, flooding the unsent pool with stale articles.
- **Fix:** Added `and now.hour < 2` — cleanup only triggers in 00:00-01:59.

### Bug #2 — SQLite DML never commits
- Python's `sqlite3` starts implicit transaction on INSERT/UPDATE/DELETE, but never auto-commits. Without `conn.commit()`, changes are rolled back on connection close.
- **7 affected functions:** `add_news`, `clear_unsent_news`, `update_news_description`, `mark_as_sent`, `add_subscriber`, `deactivate_subscriber`, `cleanup_old_news`
- **Fix:** Added `conn.commit()` after each DML.
- **DB fix:** Ran `UPDATE news SET is_sent=1` for 1373 old news that were wrongly reset. Only 1 today-news remains unsent.
- **Status:** Rewrote `database.py`, committed, rebuilt, verified working.

### User report: Digests show old news too (2026-06-26 11:30)

- After exhausting a parser's feed entries, `_seen_urls` resets and same articles repeat.
- **Fix approach:** Remove `_seen_urls` entirely. Replace cycling with `get_latest()` — always return the first (newest) entry from each source's RSS feed. User wants LATEST, not cycling.
